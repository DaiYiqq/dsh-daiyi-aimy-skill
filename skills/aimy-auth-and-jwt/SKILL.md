# aimy-auth-and-jwt · 认证与会话

认证问题很少靠"爆破"发现，更多是**信任边界**问题：签名算法、密钥强度、声明信任、会话固定、对象级授权。本技能只安排检测与证据留存，不签发越权 token、不碰真实用户。

## 何时用

- `aimy_recon` / `aimy_crawl` 发现登录、注册、找回密码、token 刷新接口。
- 页面 / 接口使用 JWT（`Authorization: Bearer` 或 cookie 里的三段式字符串）。
- 需要确认"换个用户 ID 还能不能访问"这类对象级授权问题。

## 前置条件

- 已登记范围，并使用**测试账号**；不碰真实用户账号。
- 拿到至少一个合法测试 token（测试账号正常登录获得），不要伪造他人 token。
- 明确会话相关接口：登录、登出、刷新、改密、绑定邮箱。
- 插件只做检测：验证过程只用只读 GET / 只读查询，不修改对象、不批量遍历。

## 操作步骤

### 1. 解析并审计 token

```js
aimy_jwt_audit({ token: "eyJhbGciOi...测试账号登录拿到的完整 token" })
```

- 关注输出里的算法、`kid`、`jku`、`x5u`、iss / aud / exp、角色类声明。
- 常见问题：接受 `alg: none`、HS256 弱密钥、`kid` 可被路径穿越、远程 JWKS 由请求控制。
- JWT 本来就可解码，"能读出 payload"不是漏洞，别写进报告。

### 2. 弱密钥核对（只对自有测试 token）

```js
aimy_jwt_audit({ token: "eyJhbGciOi...", secretCandidates: ["secret", "changeme", "test", "dev-secret"] })
```

- 命中只说明密钥弱；不要用命中的密钥签发越权 token 去访问真实数据。
- 把命中的候选、签名算法、验证耗时作为证据写进报告。
- 未命中不代表密钥强，报告里写"内置弱口令未命中"，不要写"密钥安全"。

### 3. 会话生命周期检查

- 登录后复制 Cookie / Token → 登出 → 用旧值再请求一次，确认是否失效。
- 改密后旧会话是否失效；刷新 token 是否可无限续期；并发会话是否可控。
- 每个请求先用 `aimy_scope({ action: "check", target: "<URL>" })` 复核，再执行。
- 结论用 `aimy_report({ action: "findings" })` 留存，写清接口、请求、观察。

### 4. 对象级授权（IDOR / BOLA）验证思路

1. 用 `aimy_crawl({ target, includeForms: true, includeJs: true })` 收集带对象 ID 的接口：`/api/users/1001`、`/api/orders?id=...`、`/api/files/<id>`。
2. 用测试账号 A 登录，记录 A 能访问的对象 ID 与响应长度（基线）。
3. 用同权限测试账号 B 的 token 请求 A 的对象 ID：同 URL、同方法，仅替换 token。
4. 若 B 得到 200 且返回 A 的数据 → 确认越权；若 403 / 404 或返回空 → 未确认。
5. 反向再验一次（A 请求 B 的对象），排除"这个 ID 本来就公开"。
- 该验证是**只读 GET**；不要修改、删除他人对象，也不要遍历 ID 批量抓取。

### 5. 认证面配置检查

- 登录接口是否有速率限制、验证码、锁定策略：观察 5~10 次失败后的响应，不持续轰炸。
- 找回密码是否泄露账号存在性（比对存在 / 不存在账号的响应差异）。
- Cookie 是否 `HttpOnly` / `Secure` / `SameSite`；JWT 是否放在 localStorage 且无 CSP 兜底。
- 默认口令只做**一次**已知测试账号的核对，不做字典爆破。

### 6. 证据留存模板

每条认证 / 会话结论按这个格式记录，直接对应 `aimy_report` 的 `evidence` 字段（token 脱敏）：

```text
[checkId] jwt-alg-trust
URL: https://example.com/api/me
请求: GET，Authorization: Bearer <测试账号 token，只保留前 8 位>
观察: 使用 alg=none 的 token 返回 200 且含本人数据
对照: 同请求使用错误签名 token 返回 401
结论: 仅在“alg=none 被接受且返回数据”成立时确认
```

- 会话类：记录登出 / 改密前后同一 token 的状态码与响应长度对比。
- 越权类：记录账号 A、B 交叉请求同一对象 ID 的响应差异，并注明两个账号的角色。
- 把 token、cookie、手机号等敏感值脱敏后再写进报告。

## 判定标准

- **JWT 弱密钥**：内置候选命中 + 能在本地验证签名一致（不访问目标）。
- **会话未失效**：登出 / 改密后旧 token 仍返回 200 且可访问本人数据。
- **越权**：两个测试账号交叉请求同一对象 ID，至少一个方向 200 且数据归属明确。
- **认证配置问题**：缺少速率限制但需要 10 次以上失败观察才算证据；单次失败不算。
- 所有结论必须附一次可复现请求；不能复现的只记为"线索"。

## 常见误报

| 现象 | 排除方法 |
|---|---|
| `alg: none` 可构造但服务器拒绝 | 实际未接受该 token，只是客户端可构造 |
| 公开接口返回 200 | 先确认该对象本来就无需登录 |
| 两个账号都能访问同一对象 | 可能是共享资源 / 公开资源，查业务语义 |
| 登出后旧 token 仍可用一会儿 | 看是否为缓存 / 短 TTL，间隔足够时间再测 |
| 登录失败响应不同 | 可能是验证码 / 锁定导致，控制变量再比对 |
| 测试账号本身权限就高 | 先确认 A、B 是同权限角色，否则结论无效 |

## 停止条件

- 需要真实用户凭据、他人 token，或要批量遍历 ID 时，停。
- 发现可越权读取真实用户数据：只保留最小证据（一条响应），不再扩大。
- 登录接口触发锁定 / 告警，立即停止并换测试账号或等待解锁。
- 任何写操作（改资料、转账、删除对象）验证一律不做。
- 授权过期或会话测试超出范围，立即停止。
